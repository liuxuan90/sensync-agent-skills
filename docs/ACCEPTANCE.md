# 跨设备验收

在使用设备安装stable完整目录，校验manifest及`manage_skill.py verify`，刷新索引后用真实需求调用Skill。记录Agent、版本、可用工具、不可用能力和实际结果。

## 巴西首轮小样本

四线分批，在葡萄牙语和英语公开资料中选取少量真实企业，分别覆盖正常、边缘、同行竞合、多机会、信息不足。不得编造企业或为了凑类型虚构机会；实际未找到的类型记录缺口。巴西只是本轮验收国家。

1. 每条机会能否解释具体产品/工序/协议及采购或设计/渠道职责？是否排除行业关键词假匹配？
2. 门槛、证据、反面证据、独立来源和日期能否追溯？关键未知是否待复核而非强打分？
3. 成品竞争与设备购买是否独立，竞争状态是否在汇总与背调显式可见？
4. 联系人身份/现职、邮箱出处和工具验证是否分开？公共邮箱未归属个人，格式推测未标已验证？
5. 草稿是否只有一个有依据的切入、三个主题、一项CTA、完整正文和签名？没有编造痛点或发件人？
6. 一个xlsx六表、中文表头、背调机会/证据列、客户/机会引用有效，企业计数无重复，内容未截断？
7. 目的地写入是否确实回读成功，人工数据是否保留，工具不足是否明确？
8. 在隔离安装目录验证更新、同版幂等、本地修改拒绝、敏感差异复核、备份和失败恢复；不要拿生产安装模拟故障。

首次未提供历史名单且未明确确认无名单时，known_customer=UNKNOWN；可以评估客户适配，但不能谎称历史排查完成或将其计为最终合格。真实研究结果、邮箱、名单和工作簿放仓库外。小样本不能证明评分已统计校准。
